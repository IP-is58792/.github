<h2>电脑和服务器不一样，不能随意改网络结构</h2>
<p>服务器可以绑多个地址、改路由表，出问题重启一下就行。办公电脑不行：改网络配置可能影响日常使用，员工也不会配合复杂的操作。</p>
<p>所以给电脑分配专线地址，重点在「尽量不动终端」。下面三种做法，从改动最小到最大排列。</p>

<h2>做法一：终端配代理</h2>
<p>电脑上把代理指向对应出口，其余配置不变。改动最小，最灵活，也最适合人员会变动的环境。</p>
<p>缺点是依赖终端操作。用户可能忘记开、忘记切，或者被其他软件覆盖设置。所以要有检查手段，不能只靠自觉。</p>

<h2>做法二：网关按设备分组</h2>
<p>在网关上按设备（MAC 或 IP）分组，不同组走不同地址。终端完全不用改，用户无感。</p>
<p>这是「办公室多设备」场景里最实用的做法。前提是网关支持按来源分流，且设备地址相对固定（建议做静态绑定）。</p>

<h2>做法三：终端直接配公网地址</h2>
<p>把公网地址配到电脑上，电脑直接持有地址。最彻底，但改动最大，也最容易出问题。</p>
<p>只建议在少数固定工位、且有人能处理配置的场景使用。普通办公环境用这个做法，维护成本会很高。</p>

<h2>无线设备怎么办</h2>
<p>无线设备共享同一个接入点，很难按设备分不同地址。常见做法是在终端侧配代理，绕开无线层的限制。</p>
<p>如果无线设备也需要固定身份，可以考虑为不同的无线网络（SSID）绑定不同的策略。但这需要设备支持，配置也相对复杂。</p>

<h2>设备多了怎么管</h2>
<p>三个动作：静态绑定（设备与地址固定对应）、分组（按业务或人员分组）、记录（谁用哪个地址）。</p>
<p>三个动作里「记录」最关键。设备一多，谁用哪个地址很快就会说不清，出问题时无法定位。</p>

<h2>验证方法</h2>
<p>每台设备实测一次出口地址，与分配表对照。再选一台断开测试，确认不影响其他设备。</p>
<p>第二项能发现「分组其实没生效」的问题。很多配置看起来分了组，实际全走默认出口。</p>

<h2>常见配置错误</h2>
<p>一是设备上有其他网络软件，覆盖了网关策略。二是终端的 DNS 设置绕过了出口。三是静态绑定没做，设备换 IP 后落到别的组。</p>
<p>三个错误都会表现为「配置对但结果不对」。排查时先看终端侧，再看网关侧。</p>

<h2>先给「最不配合的那台设备」设计做法</h2>
<p>每台电脑的配合度不一样，有人愿意改配置，有人一改就出问题。设计的做法要能在最不配合的那台设备上跑通，否则实际执行时会被绕开。</p>
<p>这也是网关分组更受欢迎的原因：终端什么都不用改，用户不会因为「懒得设置」而破坏方案。技术方案的成败，很多时候取决于它对人的要求有多低。</p>
<p>如果不具备网关分组的条件，退一步选代理配置，同时准备一份三行说明：怎么开、怎么切、出问题找谁。说明越短，执行率越高。</p>
<p>给多台电脑分配时，建议按固定映射而不是按顺序分配：谁用哪条地址写死，不随人走。顺序分配在人员变动时会乱套，固定映射虽然前期麻烦，但后续维护几乎不需要额外投入。</p>
<h2>常见问答</h2>
<h3>能不能一台电脑配多个地址？</h3>
<p><strong>答：</strong>技术上能，但日常使用没有必要，且容易混乱。</p>
<h3>手机怎么分？</h3>
<p><strong>答：</strong>手机通常在终端侧配代理，路由器层很难按设备分。</p>
<h3>需要改终端网络设置吗？</h3>
<p><strong>答：</strong>用网关分组就不用。用代理或直配地址就要改。</p>
<h3>设备换人用怎么办？</h3>
<p><strong>答：</strong>按设备分的方式不用改，按人分的要调整分配表。</p>
